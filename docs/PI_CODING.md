# Pi coding track

Run one model against the committed `pi-coding-v1` suite. Each task starts a fresh Pi session and synthetic Python project. The primary outcomes are the number of final patches passing all checks and the elapsed time from task start to the first passing edit on cases both profiles solve. This is a local Pi benchmark. Public exercise results use a different agent and protocol from Aider’s leaderboard.

```sh
uv run --locked python runner/run_pi_coding.py --config configs/pi-coding-v1/inkling-stock.yaml --output /Volumes/Expansion/coding-runs/stock-1
uv run --locked python runner/compare_pi_coding.py /Volumes/Expansion/coding-runs/stock-1 /Volumes/Expansion/coding-runs/groot-1
```

Run Groot or the experimental guided profile with the corresponding config in the same directory and a fresh output path. To add a model, copy a config, set the exact served ID and pin its launch artifact and model files. A config with the `mei` section launches one owned process and verifies the binary, metallib and model files. A config without that section attaches to an existing local OpenAI-compatible endpoint and verifies its advertised model ID. For attached endpoints the caller owns lifecycle and model provenance. Commit the new config before running. Comparison requires complete runs with the same task IDs, protocol fingerprint, agent version and task budgets. Reports can compare previously saved runs.

The first campaign pins Pi 1.6.0, 16,384 context tokens, 4,096 output tokens per request, greedy decoding, seed 17 and 480 seconds of agent wall time per task. Pi can read, edit, replace and run visible tests on allowlisted files. It receives bounded test feedback. Python runs under the existing macOS Seatbelt executor. The parent grades actual return values and exception details. Expected answers and grading code never enter the Pi tool workspace. Every edit is saved and replayed afterward. Final tests include the visible and withheld inputs. A later regression makes the final patch fail even if an earlier snapshot passed. Task deadlines and capped turns are recorded alongside the patch grade. One trajectory per task is a screen.

The eight private fixtures cover interval merging, cross-file normalization with a transient write failure, Unicode streaming, backward-compatible configuration, resumable import, overnight windows, pagination and decimal ledger math. Four public Python tasks cover affine cipher, proverb, ragged transpose and variable-length quantities. Their function inputs, expected outputs and exception messages come from the [pinned Aider Polyglot fixtures](https://github.com/Aider-AI/polyglot-benchmark/tree/7e0611e77b54e2dea774cdc0aa00cf9f7ed6144f/python/exercises/practice), originally generated by Exercism. The first two cases per public exercise are visible. Prompts and scaffolds are local adaptations. See the [Exercism license](../tasks/pi-coding-v1/LICENSE-Exercism). Tests in `runner/tests/test_pi_coding.py` verify the starters and reference implementations.

All three bundled profiles use the same local Mei 0.18.0 experimental binary (Mei 56a654d, backend c2d0cfa). Stock uses its original loop path. The 0.2 profile sets MEI_SPIKE_LOOPCD=0.2. Both use the same Inkling vocabulary-Q4 weights. Groot uses the text-only 4.5 bpw RCO-role export. Source patch and binary provenance are in /Volumes/Expansion/mei-loopcd-gYnk6wpe. Server caching is off. Comparisons measure the selected model profiles on this Mac.

The [first three-profile comparison](../results/pi-coding-v1/2026-11-25/README.md) includes archived manifests and results that can be passed directly to the comparison command. When launching managed profiles consecutively on the same port, allow the previous server's TCP connections to leave TIME_WAIT before starting the next profile.

## Pi coding v2 · benchmark-v9.12.0

The new version scores four tasks. Four private repairs exercise interactions between requirements in a multi-file Python project. Batch ledger combines replay, rollback and legacy snapshots. Build waves combines scoped validation, cache invalidation and deep dependency chains. Temporal overlay combines revision selection, retraction, interval clipping and coalescing. Feed recovery combines replayed events, partial checkpoints and empty pages across a worker restart. All four tasks are new to this version. A 4/4 and an 11/12 belong to different suites.

The feed fixture presents an issue against existing code, following the issue-repair format of [SWE-bench](https://www.swebench.com/). Its grader checks the saved state across interruptions and restarts, drawing on [τ-bench’s end-state evaluation](https://arxiv.org/abs/2406.12045). All prompts, fixtures and checks in v2 are locally authored.

Use the same runner with a v2 config and a fresh results path. The manifests pin the suite, sources and budgets. Groot, Qwen, Ornith and Logics-SWE come from the active roster. Stock Inkling and experimental LoopCD 0.2 are additional comparison profiles. The five MLX profiles use the verified Mei 0.18.0 experiment binary; the Logics-SWE IQ4_XS profile verifies and launches its roster-pinned llama.cpp build and GGUF. Each profile uses greedy generation, seed 17, a 16,384-token context, 4,096 output tokens per request, and 480 seconds per task.

```sh
uv run --locked python runner/run_pi_coding.py --config configs/pi-coding-v2/qwen.yaml --output /Volumes/Expansion/pi-coding-runs/qwen-v2-1
```

The comparator reads historical v1 receipts directly. To reproduce the original v1 protocol fingerprint exactly, use commit 8a35f2dd.
