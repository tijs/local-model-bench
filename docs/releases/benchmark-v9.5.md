# local-model-bench benchmark-v9.5

Adds native Clover cache controls with two independent cold processes per case:
repeat, growing tool history and continuation after a seven-token partial block.
A pass requires cold determinism, actual cache hits only on the warm leg,
identical content/reasoning/tool arguments and the correct tool contract.
These are unscored diagnostics with fresh configs and process ownership.

The first original-runtime cache attempt stopped for swap growth during its
second load. A fresh attempt passed seven stable recovery observations but
still stopped for sustained warning pressure on its second load. Both raw
attempts, post-run hashes and reviews are preserved; neither has a cache verdict
or task score. A stable host window alone did not resolve the loading behavior.

An isolated loader candidate requests each shared weight buffer's residency
before CPU filling rather than only after model initialization. It inserts six
lines and changes no payload, kernel or tensor arithmetic. The pinned base,
patch, source tree hash, license and build evidence are public. Seven selected
CPU tests and upstream lint pass. The new binary passed five native tool checks
under normal pressure with zero swap growth; repeated-load/cache qualification
is still pending. It is an experiment, not a verified memory fix or upstream
release.

All 684 model-free benchmark tests pass (98.463 seconds); changed Python files
pass Ruff and ty. The recovery condition is bounded, checks actual VM byte
counters, pressure and flat swap, and keeps every global stop limit. No
free-percentage gate, background app closure or system-wide purge was added.

Scored helpers, validators, launch parent, supervisor and existing serving
profiles are unchanged from v9.4. Historical grades remain append-only. Clover
still has no full benchmark score. See the [diagnostic guide](../CLOVER_NATIVE.md)
and [candidate preparation](../../artifacts/candidate-system-campaign-20261101/kapitsa-loader-residency-preparation/).
