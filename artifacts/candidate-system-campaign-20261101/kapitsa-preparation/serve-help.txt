kapitsa serve [--model MODEL] [options]

  --model MODEL          35b, 27b, 4b (full names: kapitsa --help; <model>:<variant> for another
                         precision), org/name[@revision], a model folder, or a .gguf file (converted
                         once: kapitsa import). Default: asked in a terminal; else the model picked last if
                         it is downloaded, else the best model for this Mac. Downloaded on first use.
  --host HOST            listen address (default 0.0.0.0: this Mac and its network; 127.0.0.1: this Mac
                         only, like --private)
  --port PORT            default 8000
  --private              this Mac only: listen on 127.0.0.1, stay out of sight of Kapitsa on the other Macs
                         and never send them requests. By default the server is visible on the network
                         (Bonjour), with no password: kapitsa cluster on any Mac lists it
  --peer HOST[:PORT]     another Mac's Kapitsa server, for networks that block Bonjour between Macs (most
                         office Wi-Fi): read as the Macs Bonjour finds (also KAPITSA_PEERS, ~/.cache/kapitsa/peers)
  --local                run the model here even when another Mac on the network runs it whole. By default a
                         Mac that would not hold the model whole (it does not fit, or streams experts from
                         the SSD) sends its requests to one that does, which kapitsa serve finds by itself
  --api-key KEY          require "Authorization: Bearer KEY" or "x-api-key: KEY" (the chat page asks for
                         it once)
  --allow-switch         a request naming another model, or POST /v1/models/switch, loads it (may download
                         gigabytes; 503 + Retry-After meanwhile). Default off: the "model" field is ignored.
                         Without --api-key it keeps the server on this Mac, as --private does
  --model-id ID          the model's name in the API (default: the model's name)
  --context N            context per conversation: tokens, k or m of them (128k, 1m), or max (the
                         model's limit). Default: the model's limit (128K where it states none), or less where this
                         Mac's memory is tight (the most that keeps the draft model). --ctx N works too
  --slots N              requests that run at once, each keeping its conversation ready for instant
                         follow-ups; more wait for a free slot (default: up to 4, as memory allows)
  --dflash auto|none|DIR DFlash2 drafter: auto (default) takes the one downloaded with the model;
                         none decodes with the model's MTP head
  --spec N               MTP draft depth without a drafter (default per model; 0 = no speculation);
                         Dory with --loop-kv per-loop: drafts per cycle (default 2 at 1-2 loops, 3 at 3-4)
  --mem-budget GB        GPU memory Kapitsa may hold (default: what macOS recommends for this GPU, a
                         little less; kapitsa doctor shows it)
  --prefill-chunk N      prompt tokens per prefill pass (default 2048, 1024 when memory is short)
  --disk-cache SIZE      SSD prefix cache: conversations kept on the SSD, also across restarts, in
                         ~/.cache/kapitsa/prefix-cache. auto (default): a quarter of the free space beyond
                         10 GiB, at most 32 GiB; a size (16G) caps it; 0 turns it off. Not every model
                         has it yet (the Qwen3.5-family models and Dory do)
  --loops N              Dory: the shared block's loops per token, 1-4 (default 2, NVIDIA's recommendation;
                         more is latent thinking: slower, more accurate). Requests choose their own with
                         "loops" or a reasoning effort (low 1, medium 2, high 4)
  --loop-kv MODE         Dory: last-loop (default: one cache per layer, the size of a 1-loop model's) or
                         per-loop (a cache per loop, as NVIDIA's vLLM commands run it; more memory)
  --timing WHAT          what the request log and the chat page show of the wait before the first token:
                         ttft (time to the first token), prefill (prompt tokens read per second, the
                         uncached ones only: a cache hit counts just its new tokens) or both (default)
  --split HOST:PORT,...  Qwen3.8-Flash-Next split across Macs by layers: this Mac holds the first ones and
                         takes the requests, each `kapitsa stage` listed holds the layers after them, in
                         order (kapitsa stage --help)
  --image-max-pixels N   images: resize larger ones to about N pixels (default 1200000, about what
                         Anthropic's API sends Claude: a 2880x1800 screenshot becomes 1376x864, 1.2K
                         tokens; Nemotron 3.5 Bolt and Super-VL 1400000, which small text needs there;
                         more keeps finer detail and takes longer; 0 = the model's own limit)

Endpoints: GET / (chat page), POST /v1/chat/completions (OpenAI), POST /v1/responses (OpenAI Responses),
POST /v1/messages and /v1/messages/count_tokens (Anthropic), POST /v1/draft (read a user's draft ahead),
GET /v1/models, GET /health, GET /cluster (what the server tells the other Macs).
Images (every catalog model reads them): OpenAI image_url parts, Anthropic image blocks and Responses
input_image, as data: (base64) or http(s) URLs. Video is not supported.
Tuning switches (NI_* variables): docs/usage.md.
